## الفكرة في سطرين

الترجمة الآلية قد تنقل الكلمة وتُفسد معناها: إمّا **تهويل** (Holy War للجهاد)، أو **إسقاط** مفهوم من ثقافة أخرى (Priest للإمام)، أو **تمييع** يُفقد المصطلح حدّه الشرعي (Charity للزكاة).
«ظِلال» يرصد هذه الظلال في الاتجاهين، ثم يعيد كل مصطلح إلى تعريفه في مصدر معتمد **برابط مباشر**. القاعدة الحاكمة: **لا جواب بلا مصدر**.

**المستخدم المستهدف:** المترجم والمحرر في جهات التعريف بالإسلام، وصانع المحتوى متعدد اللغات.

## ما الذي يعمل الآن

| المكوّن | الوصف |
|---|---|
| **المعجم الموثّق** | قاعدة مصطلحات منقولة حرفيًا من [موسوعة المصطلحات والقواميس الإسلامية المترجمة](https://terminologyenc.com/ar)، لكل مصطلح تعريفه العربي وترجمته الإنجليزية ورابطه. بحث يفهم العربية بلا تشكيل ومع «ال» أو بدونها، والإنجليزية والكتابة الصوتية (zakah/zakat). |
| **اسأل ظلال (البوت)** | يجيب من القاعدة مع رقم المرجع ورابطه، ويدقق المقالات الملصوقة. **يمتنع** حين لا يجد مرجعًا، و**يحيل** أسئلة الفتوى وترجمة الآيات إلى أهلها. |
| **مدقق الترجمة** | خريطة ظلال ملوّنة حسب النوع، وميزان الأمانة (تهويل ← أمين → تمييع)، ومؤشر سلامة، وبطاقة لكل موضع فيها: لماذا هو ظل، وتعريف المصدر، والبديل المقترح، وزر تطبيق البديل، وزر الإحالة للمختص. |
| **مختبر القياس** | يشغّل مجموعة الاختبار داخل المتصفح عند فتح الصفحة، ويقارن بقاعدة الإصدار السابق على الحالات نفسها. |
| **الذكاء التوليدي المقيّد (اختياري)** | Gemini عبر وظيفة سحابية تخفي المفتاح؛ يصوغ الجواب من المقتطفات المرفقة فقط، ثم **يتحقق المتصفح آليًا** من أن كل مرجع موجود في القاعدة ويحذف غيره. |

## المعمارية: كيف يعمل الذكاء الاصطناعي

```
النص/السؤال
  │
  ├─ 1) تطبيع (تشكيل، همزات، تاء مربوطة، كتابة صوتية)
  ├─ 2) توجيه بحواجز قبل النموذج:
  │     • سؤال فتوى («ما حكم/هل يجوز…»)  ← إحالة + تعريف المصطلح فقط
  │     • ترجمة آية                       ← إحالة إلى مجمع الملك فهد
  │     • نص طويل                         ← تدقيق
  │     • مصطلح غير موجود                ← امتناع
  ├─ 3) رصد سياقي للظلال (data/shadows.js): قواعد مشروطة بسياق الجملة
  ├─ 4) استرجاع (RAG) من القاعدة الموثّقة: التعريف + الترجمة + الرابط
  ├─ 5) [اختياري] توليد مقيّد بـ Gemini على المقتطفات المسترجعة فقط
  └─ 6) تحقق آلي من المراجع + وسم كل مخرج بمستوى ثقته
```

**مستويات الثقة في كل مخرج:**
🟢 نص المصدر (حرفي) · 🔵 تحليل ظلال (قاعدة صاغها الفريق وتحيل للمصدر) · 🟡 صياغة الذكاء الاصطناعي (مقيّدة ومفحوصة) · 🔴 يحتاج مختصًا.

**لماذا هذا التصميم؟** المحرك المحلي يعمل دون إنترنت ودون نموذج، فنتائجه قابلة للتكرار والتحقق. والنموذج التوليدي طبقة إضافية لا يقوم عليها المنتج: إذا تعطل أو نفد الرصيد يعود البوت تلقائيًا إلى وضع المعجم.

## النشر (رابط حي مع الذكاء التوليدي)

1. ارفع المستودع إلى GitHub **عامًا (Public)**.
2. في [Netlify](https://app.netlify.com): **Add new site → Import an existing project → GitHub** واختر المستودع. الإعدادات تُقرأ من `netlify.toml`.
3. **الذكاء التوليدي يعمل تلقائيًا** عبر Netlify AI Gateway: يحقن Netlify المتغيرين `GEMINI_API_KEY` و`GOOGLE_GEMINI_BASE_URL` للوظيفة دون أي مفتاح منك، ويُحتسب الاستهلاك من رصيد Netlify.
   - **بديل:** لتوفير رصيد Netlify، أضف مفتاحك المجاني من Google AI Studio في **Project configuration → Environment variables** باسم `GEMINI_API_KEY`؛ عندها تتصل الوظيفة بـ Google مباشرة.
   - `GEMINI_MODEL` (اختياري) = `gemini-3.8-flash`
4. افتح `https://<موقعك>/api/ask`: يجب أن ترى `{"ok":true,...}`، ويوضح الحقل `via` مسار الاتصال.
5. تأكد أن ظهور المشروع **Public** (زر **Make public** في صفحة المشروع)، وإلا طلب Netlify تسجيل الدخول من الزوار.

> ⚠️ لا تضع المفتاح في أي ملف داخل المستودع. وخاصية السحب والإفلات في Netlify تنشر الصفحة دون الوظيفة السحابية، فيعمل الموقع في وضع المعجم فقط.

## الاختبار

```bash
npm test        # يشغّل tools/run-tests.mjs على المحرك نفسه الذي يعمل في الصفحة
```

المجموعة في `data/tests.js`: حالات تشويه، وترجمات سليمة لقياس الإنذار الكاذب، وأسئلة للبوت لقياس الامتناع والإحالة. وأدرجنا عمدًا حالات يخطئ فيها المحرك (H02–H05) لبيان حدوده.

**المقاييس:**
- **كشف التشويه:** نسبة حالات التشويه التي نُبّه عليها.
- **الإنذار الكاذب:** نسبة الترجمات السليمة التي نُبّه عليها خطأً.
- **سلوك البوت:** نسبة الإجابات أو الامتناعات أو الإحالات الصحيحة.

**خط الأساس:** قاعدة الأنماط في الإصدار السابق من المنصة، منقولة كما هي في `ZILAL_BASELINE_V0`.

النتائج الحالية تظهر في قسم «مختبر القياس» في الصفحة، وفي مخرجات `npm test`.

## حدود ظلال (بصراحة)

- **حدود الرصد المحلي:** يعتمد على قواعد صريحة، فيفوته التهويل أو التمييع بصياغة غير مباشرة. يقلّل التحليل التوليدي هذا القيد ولا يلغيه.
- **ثقة القواعد:** قواعد الظلال (`data/shadows.js`) تحليل صاغه الفريق، وتحتاج اعتماد المختص الشرعي. انظر `REVIEW_CHECKLIST.md`. لكل قاعدة حقل `reviewed`.
- **التعريفات الإنجليزية في المصدر:** بعضها غير مطابق؛ أزلنا 102 قيمة ظاهرة الخلل، ويبقى النص العربي هو المرجع عند الاختلاف.
- **النطاق:** يدقق حاليًا الترجمة الإنجليزية فقط.
- **طبيعة الاختبار:** مجموعة الاختبار داخلية وصغيرة، وليست دراسة مستخدمين.
- **ما لا يفعله:** لا يفتي، ولا يترجم آيات القرآن ولا الأحاديث.

### English summary

**Zilal** flags cultural "shadows" in English translations of Islamic terms: exaggeration (*tahweel*, e.g. "holy war"), cultural projection (*isqat*, e.g. "priest" for imam), and dilution (*tamyee*, e.g. "charity" for zakah).

Every explanation is grounded in a verbatim definition from the challenge-approved sources, with a per-term link.

The core engine is deterministic and runs fully in the browser, so its results can be re-tested. An optional Gemini layer, served through a Netlify function, writes answers only from retrieved source snippets, and the client verifies every citation automatically.

The bot refuses when no source exists, and refers fatwa and Qur'an-translation requests to qualified authorities.
